## 2. Deterministic Tie-Breaking Rules (When Cues Span Multiple Pillars)

137 of the 211 open issues (**64.9%**) exhibit genuine signals from two pillars. To keep primary assignments reproducible across reviewers, apply these four precedence rules in order:

1. **Broken Contract Beats Context (`Reliability > Adoption / Scalability / Extensibility`):** If an issue reports a crash, regression, silent wrong output, race condition, or unhandled exception in an *already supported* feature, assign **Primary: Reliability** and record the surrounding workflow as Secondary. *Examples:* [#4234](https://github.com/SQLMesh/sqlmesh/issues/4234) and [#5341](https://github.com/SQLMesh/sqlmesh/issues/5341) occur inside dbt projects (`Primary: Reliability`, `Secondary: Adoption`); [#4250](https://github.com/SQLMesh/sqlmesh/issues/4250) breaks the documented `CustomLoader` hook (`Primary: Reliability`, `Secondary: Extensibility`); [#6209](https://github.com/SQLMesh/sqlmesh/issues/6209) returns already-expired cache entries on slow snapshot fetches (`Primary: Reliability`, `Secondary: Scalability`). *Exception:* When a third-party dbt package uses Jinja syntax SQLMesh has not yet implemented ([#5295](https://github.com/SQLMesh/sqlmesh/issues/5295) `dbt_expectations` `-%}` test blocks), assign `Primary: Adoption`, `Secondary: Reliability`.
2. **Asymptotic / Fleet Cost Beats Ergonomics (`Scalability > Adoption`):** When a feature request is motivated by model count ($N > 100$), data size (100M+ rows / TB partitions), CI runtime growth, or eliminating $O(N)$ manual repetition across 90% of models (`model_defaults` for `blueprints` [#4928](https://github.com/SQLMesh/sqlmesh/issues/4928), subfolders [#4996](https://github.com/SQLMesh/sqlmesh/issues/4996), `grants` [#5602](https://github.com/SQLMesh/sqlmesh/issues/5602)), assign **Primary: Scalability** and **Secondary: Adoption**.
3. **Mechanism vs. Consumer Goal (`Extensibility` vs. `Adoption`):**
   - Assign **Primary: Extensibility** when the requester explicitly asks for a **hook, event, config toggle, or open interface so external code/tools can build on SQLMesh without forking or subclassing internals** (for example, [#5600](https://github.com/SQLMesh/sqlmesh/issues/5600) avoiding forking `SnowflakeEngineAdapter`, [#5865](https://github.com/SQLMesh/sqlmesh/issues/5865) `audit pass` notification hook, [#5997](https://github.com/SQLMesh/sqlmesh/issues/5997) Ossie semantic-layer generator, [#5814](https://github.com/SQLMesh/sqlmesh/issues/5814) ADBC BYOD interface).
   - Assign **Primary: Adoption** (with `Secondary: Extensibility` where applicable) when the requester wants **built-in SQLMesh support** for an engine, SQL clause, authentication flow, or migration bridge so their team can use SQLMesh out of the box (for example, [#5821](https://github.com/SQLMesh/sqlmesh/issues/5821) exporting `manifest.json` expressly framed around overcoming hesitation to adopt SQLMesh; [#5066](https://github.com/SQLMesh/sqlmesh/issues/5066) Azure Entra ID auth; [#4453](https://github.com/SQLMesh/sqlmesh/issues/4453) ClickHouse RMVs).
4. **Never Force-Fit Internal Housekeeping (`Uncategorized`):** Issues limited to internal SQLMesh contributor CI speedups ([#6147](https://github.com/SQLMesh/sqlmesh/issues/6147) sharing a Playwright browser page across repo e2e tests), non-urgent library swaps with no user-visible pain ([#3451](https://github.com/SQLMesh/sqlmesh/issues/3451) `psycopg2` -> `psycopg3`), or pure code-curiosity questions ([#5581](https://github.com/SQLMesh/sqlmesh/issues/5581) asking why `MAX_TABLE_COMMENT_LENGTH = 1024`) go to **Uncategorized** with a one-line reason.
