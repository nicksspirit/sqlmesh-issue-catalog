**Verdict definitions:**
- **Aligned:** `>= 80%` of labeled issues map to a single primary pillar whose strategic goal matches the label's scope.

- **Orthogonal:** Label slices by warehouse adapter (`Engine:*`) or UI surface (`Project:*`) independent of strategic pillar priority (or sits unused at `0` issues).

## 4. Triage Process Suggestions

1. **Track Primary Pillar as a Required GitHub Project Single-Select Field (Not Flat Labels):** Flat GitHub labels allow `0` or `3+` values—which is why 60 open issues have zero labels and 14 have contradictory `Feature` + `Improvement` tags. Configure a Linux Foundation org-level GitHub Project v2 with a required **`Primary Pillar`** single-select (`Reliability`, `Scalability`, `Adoption`, `Extensibility`) and optional **`Secondary Pillar`** field, seeded directly from [`03-pillar-catalog.md`](./03-pillar-catalog.md).
2. **Automate Intake Labeling via GitHub Actions + Cue Rubric:** Deploy a lightweight `.github/workflows/issue-triage.yml` workflow on `issues: [opened, edited]` that (a) auto-applies `engine:*`, `area:*`, `data-correctness`, `core: planner-state`, and `ecosystem-integration` from [`02-cue-rubric.md`](./02-cue-rubric.md) cues, and (b) adds a temporary `needs-triage` status until a maintainer confirms the Primary Pillar in weekly triage.
3. **Upgrade Issue Forms (`.github/ISSUE_TEMPLATE/`):** Require structured fields on Bug and Feature forms (SQLMesh version, target engine gateway, approximate model count `<50 / 50–500 / 500+`, and whether silent wrong data occurred). Requiring minimum reproduction context prevents zero-body issues like [#5956](https://github.com/SQLMesh/sqlmesh/issues/5956) and 10-word requests like [#5873](https://github.com/SQLMesh/sqlmesh/issues/5873) and [#5875](https://github.com/SQLMesh/sqlmesh/issues/5875).
4. **Weekly Two-Track Triage Cadence:** Review `Reliability` + `data-correctness` continuously (zero-wait SLA for silent data loss and regressions); review `Scalability`, `Adoption`, and `Extensibility` RFCs bi-weekly in Technical Steering Committee (TSC) roadmap sessions, grouping decomposed epics ([#6014](https://github.com/SQLMesh/sqlmesh/issues/6014)/[#6018](https://github.com/SQLMesh/sqlmesh/issues/6018)/[#6019](https://github.com/SQLMesh/sqlmesh/issues/6019) and [#6020](https://github.com/SQLMesh/sqlmesh/issues/6020)/[#6021](https://github.com/SQLMesh/sqlmesh/issues/6021)/[#6024](https://github.com/SQLMesh/sqlmesh/issues/6024)/[#6025](https://github.com/SQLMesh/sqlmesh/issues/6025)) under parent tracking issues.

## 5. Stakeholder Decisions Needed & Open Questions

1. **Open Question — GitHub Project Column vs. `state: open`:** This catalog defines `pending = open` across [`SQLMesh/sqlmesh`](https://github.com/SQLMesh/sqlmesh/issues) (`211` issues). `SQLMesh/sqlmesh` has `has_projects: true`, so if stakeholders track a narrower "Pending / Triage" column on a private or Linux Foundation GitHub Project v2 board, confirm the Project number so we can filter or sync these 211 classifications directly into that board.
2. **Decision — Bulk Backfill of the 60 Unlabeled Open Issues:** Approve running a one-time `gh issue edit` script using [`03-pillar-catalog.md`](./03-pillar-catalog.md) to apply missing `Bug` / `Engine:*` / `Project:*` tags—especially to the 38 unlabeled Reliability bugs created since the March 2026 governance transition.
3. **Decision — Pillar Storage Mechanism:** Choose between **(a)** a GitHub Project v2 single-select field (recommended: enforces exactly one Primary Pillar) vs. **(b)** four flat `pillar: reliability|scalability|adoption|extensibility` repo labels (visible directly in standard repo issue lists without opening Projects).
4. **Decision — SQLGlot-Rooted Issues in `SQLMesh/sqlmesh`:** Several open Reliability bugs ([#5044](https://github.com/SQLMesh/sqlmesh/issues/5044), [#5218](https://github.com/SQLMesh/sqlmesh/issues/5218), [#5288](https://github.com/SQLMesh/sqlmesh/issues/5288), [#5604](https://github.com/SQLMesh/sqlmesh/issues/5604), [#5649](https://github.com/SQLMesh/sqlmesh/issues/5649), [#5770](https://github.com/SQLMesh/sqlmesh/issues/5770), [#5948](https://github.com/SQLMesh/sqlmesh/issues/5948)) stem from `tobymao/sqlglot` parsing/generation or SQLMesh's `sqlglot` version pin. Decide whether to keep these open in `SQLMesh/sqlmesh` until the dependency bump ships or transfer/close upstream with an `upstream: sqlglot` tag.
